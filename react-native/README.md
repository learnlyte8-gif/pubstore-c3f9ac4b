# PUBSTORE — React Native shell

Native Android/iOS shell for the PUBSTORE app. This folder is the
React-Native counterpart of the web project in the repo root. It is **not**
generated by `react-native init` — only the app-specific files are checked
in (`package.json`, `App.tsx`, `src/`, `index.js`, etc.). You finish
scaffolding the native projects on your machine.

## What this gives you

- A native shell that loads the deployed PUBSTORE web app inside a hardened
  `react-native-webview` so you can run the whole product on a real device
  immediately.
- A real React-Navigation bottom-tab structure (Home, Categories, Messages,
  Wishlist, Profile) mirroring the web `AppShell`, ready for you to
  progressively replace each tab with native screens.
- A pre-wired Supabase client using the same project URL + anon key as the
  web app (`src/services/supabase.ts`).
- Stubs for push notifications (Firebase), maps, image picker, geolocation,
  and a Lovable AI Gateway helper, all matching the web feature set.

## One-time setup on your machine (Android Studio)

The Lovable sandbox has no React Native CLI / Android SDK, so the native
`android/` and `ios/` folders are generated locally:

```bash
# 1. Copy this folder out of the web repo
cp -R react-native ~/pubstore-rn
cd ~/pubstore-rn

# 2. Generate the native shells without overwriting our app code
npx @react-native-community/cli@latest init pubstore \
  --version 0.75.4 --skip-install --directory .tmp-rn
cp -R .tmp-rn/android .tmp-rn/ios .tmp-rn/.eslintrc.js .tmp-rn/.prettierrc.js \
      .tmp-rn/.watchmanconfig .tmp-rn/metro.config.js .tmp-rn/jest.config.js .
rm -rf .tmp-rn

# 3. Install JS deps + iOS pods
npm install
cd ios && pod install && cd ..

# 4. Open in Android Studio:  File → Open → ~/pubstore-rn/android
#    Or run directly:
npx react-native run-android
```

> The init step is what creates the Gradle wrapper, `MainActivity`,
> `Info.plist`, etc. After it finishes, our `App.tsx` / `index.js` /
> `src/` win because they were already in place.

## Configuring the app id / version

The web project ships as `app.lovable.14b25a14b8c040f29b8231f038ad2828`
v11. After `react-native init`, set the same identity in:

- `android/app/build.gradle` → `applicationId`, `versionCode = 11`,
  `versionName = "11.0"`
- `ios/pubstore/Info.plist` → `CFBundleIdentifier`,
  `CFBundleShortVersionString`, `CFBundleVersion`

## Building a release AAB

```bash
cd android
./gradlew bundleRelease
# AAB:  android/app/build/outputs/bundle/release/app-release.aab
```

Sign with the same keystore you already use for the Capacitor build
(`scripts/build-android-aab.sh` documents the env vars).

## Architecture map (web → native)

| Web (`src/`)                       | Native (`react-native/src/`)             |
| ---------------------------------- | ---------------------------------------- |
| `components/AppShell.tsx`          | `navigation/RootTabs.tsx`                |
| `pages/Home.tsx`                   | `screens/HomeScreen.tsx`                 |
| `pages/Categories.tsx`             | `screens/CategoriesScreen.tsx`           |
| `pages/Messages.tsx`               | `screens/MessagesScreen.tsx`             |
| `pages/Wishlist.tsx`               | `screens/WishlistScreen.tsx`             |
| `pages/Account.tsx`                | `screens/ProfileScreen.tsx`              |
| `pages/Rides.tsx`, `Driver.tsx`    | `screens/RidesScreen.tsx`                |
| `pages/ProductDetail.tsx`          | `screens/ProductDetailScreen.tsx`        |
| `pages/Cart.tsx`                   | `screens/CartScreen.tsx`                 |
| `pages/Auth.tsx` + Onboarding      | `screens/AuthScreen.tsx` + `OnboardingScreen.tsx` |
| `integrations/supabase/client.ts`  | `services/supabase.ts`                   |
| `lib/push.ts`                      | `services/push.ts`                       |
| `hooks/useUserLocation.ts`         | `services/location.ts`                   |

Until you finish porting a screen natively, the WebView fallback in
`screens/WebFallbackScreen.tsx` loads the matching route on
`https://pubstore.lovable.app`, so the app is fully usable from day one.

## Suggested porting order

1. **Auth + Onboarding** — replace the WebView with native screens hitting
   Supabase directly (`services/supabase.ts`).
2. **Home / Categories** — read the same `products` / `categories` tables;
   reuse images straight from Supabase Storage.
3. **Rides** — wire `react-native-maps` to the same `rides` table and
   functions as the web `useRides` hook.
4. **Messages** — hook into the same realtime channels used by
   `useChatNotifications`.
5. **Wallet / Payments** — call the existing Supabase Edge Functions
   (`paypal-*`, `pesepay-*`) over HTTPS.
